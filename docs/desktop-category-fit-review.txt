Cause
All 14 original category pictures are square 160/240px files. The desktop 4:3
frame removed 25% of their vertical content, and the caption covered more.
For Lessons this preserved the raised hand/head but hid torso, forearm/desk.
A different focal point alone could not reveal both ends of the source.

Correction
Only 15 CSS lines, inside the existing min-width:1000px media rule:
- full 1:1 photo area, with object-fit:contain and a separate caption row below;
- automatic outer category-card height, min 48px caption at normal root text;
- no desktop category-photo dark scrim, so original details/colors are clearer;
- no desktop category image zoom on hover; card lift/arrow feedback remain;
- same 4 desktop columns, spacing, vectors, labels, selected/focus styling.

At 1440px all 14 photo areas measured 257.5x257.5; all captions start exactly at
the photo bottom, not over it. All 14 cards measured 305.5px tall at normal BG
text. Previously the visible frame was 257.5x193.125 with a 45.8px overlay.
Lessons now shows the available original raised hand, torso, forearm and desk.
Sports stance/feet, groomer dog paws, consultation papers and lower action
details in the other categories are no longer removed by frame/label overlap.
All 14 original images were visually inspected and loaded in the browser.
No image was generated, replaced, cropped on disk or recolored.

Scope kept unchanged
- Mobile/tablet through 999px (including the approved narrow-label fallback).
- Subcategory tiles, All-services control, skeletons, summary and business cards.
- All original assets/focal source maps, query/state/history, filtering, prices,
  bookings, analytics, BG/EN, theme handling, APIs/data/dependencies/config.
- Existing image sources and resolution: displaying more of the same source
  does not invent missing content. A source already cut at its own edge cannot
  reveal pixels outside that original file.
