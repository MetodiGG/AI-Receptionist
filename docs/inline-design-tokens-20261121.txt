GoRez inline discovery — bold glass token review — 2026-11-21

Scope
-----
The active design is the always-visible fourteen-category grid, inline child
services, sticky espresso filter summary and refined existing business cards.
It is not the prior guided/next-step/panel redesign. No publication is implied.

app/inline-discovery.css uses --inline-* variables on the customer home only
when its inline category component exists. app/premium-discovery-cards.css
uses --premium-card-* variables on the homepage business grid. Neither file
redefines generic --ink/--paper/--surface tokens or targets h1, the main search
form, its heading, or .discovery-query. Existing form markup remains exactly
the baseline bytes; its SHA-256 is:

Glass compositing and espresso
-----------------------------
The frosted category/child panel uses 89% to 94% --inline-surface with a 16px
backdrop blur; its opaque fallback uses the same surface. Testing the actual
alpha endpoints over black and white bounds covers every possible backdrop
RGB channel before the additional decorative border layer. Conservative
minimum secondary-text contrast is 4.538:1 light and 5.729:1 dark. The light
89% endpoint passes narrowly: do not lower its opacity without recalculating.

The sticky bar has an opaque #2F211B fallback and #2F211BF2 (242/255 opacity)
when backdrop filtering is supported. Its conservative worst case is white
behind the translucent espresso. At that bound:

#FFF4E8 normal summary text                 12.32:1
#E9CBB3 secondary captions/hint              8.69:1
#FFF4E8 on #FFF4E80D category/area chip      10.61:1
#FFF4E8 on #F47A3624 service chip             9.88:1
#FFF4E8 on opaque #865438 chip hover          5.80:1
#FFF4E8 on #3E2D23 disabled select           12.07:1

Chip ratios include both compositing layers, not just the nominal espresso
color. The disabled select explicitly keeps opacity:1 and the light text fill.
Its one native option truthfully describes automatic server order: proximity
and relevance for browse; relevance and distance for a query. It is not a
page-only sorting control or a promise of independently selectable nearest
sorting. There is no added Today filter or unsupported appointment badge.

Layout and accessibility contracts
----------------------------------
Category CSS: two mobile columns, three at 700px, four at 1000px. Inline
children: two columns, three at 1200px. Font-relative container queries allow
two category columns at 32rem and a single category/child column at 14rem,
so enlarged default type can take precedence over a rigid column count.
Labels and filter chips wrap complete words rather than hiding text with
ellipsis. Chip, area and native-sort targets are at least 44px high.

The espresso summary starts in normal flow and becomes sticky 8px from the
viewport top only after ResizeObserver measurement confirms that its positive
height is at most min(240px, 30% of viewport height). Taller enlarged-text or
short-viewport summaries stay nonsticky. The nearest discovery home receives
--inline-summary-offset equal to ceil(height)+24px while safe, otherwise 0px;
cards/headings use that measured scroll margin with a 190px fallback. Cleanup
disconnects observation, removes the resize listener and restores the previous
scoped property. Browsers without ResizeObserver remain safely nonsticky.
The home alone uses overflow-x:clip and overflow-y:visible so its ancestor
cannot trap sticky positioning. Reduced motion disables the tile animations.
The panel has a presentation-only grid presence wrapper (200ms natural-height,
opacity and 8px offset). Closing immediately sets inert and aria-hidden, retains
only committed visual content for the short exit, then clears it. Reduced motion
closes immediately; quick reopen cancels exit cleanup. It does not delay URL,
selection or request changes. The desktop wrapper shares the 1120px rail width.
The category grid and inline children map all accepted items without a More
slice. The untouched non-home child picker retains its own existing behavior.

Counts say actual unique rows shown, not cataloguePage.total: that total is
computed before native hydration/revocation checks. Any “more results” marker
comes from an actual positive nextOffset, never a fabricated total or slot count.

Frozen baseline and verification
--------------------------------

and checks Git-blob hashes against current bytes for all existing API routes,
hooks, existing lib data/taxonomy/config/booking/media code (navigation-state
code remains an authorized exception), booking/media components, legacy CSS,
package.json, pnpm-lock.yaml and next.config.mjs. All 1,889 baseline public

The homepage card source differs only by the exact quick-choice raster-artwork
to existing Icon(calendar) substitution; default artwork and all action logic
remain baseline-identical, covered by a separate normalized-source assertion.
New inline-copy/UI files and authorized discovery search/subcategory state
changes are not blocked by that freeze. The service-preview cap remains two.

Run locally:
node --test tests/inline-discovery-visual-scope.test.mjs

This static/token test supplements the separate component and state tests.
Its breakpoint checks evaluate CSS declarations; they are not screenshots,
physical-device measurements or a claim of complete WCAG certification.
Rendered mobile/desktop, default-font enlargement, keyboard, light/dark and
production CSS-order review remain necessary. No DB/API/provider calls,
booking submissions, notifications or production writes are made by this test.
